The pipeline

How a request becomes a verified answer

  1. Read the request. The Client splits the task into sub-goals such as geocoding, weather, currency, or a document question.
  2. Find tools. The knowledge graph shortlists services by capability, not by name alone.
  3. Check compatibility and evidence. Ontology types, units, trust scores, breaker state, and Auditor claims filter the shortlist.
  4. Execute and recover. The Client composes a typed chain, calls providers, and substitutes a compatible tool when one fails.
  5. Record the trace. Every decision, message, latency, and failure is stored so you can inspect or export it.

Grounded answers

Documents

Use the Documents page when an answer depends on material that is not in the service catalogue. Upload a file, select it, then ask a question. The answer stays on the page and includes the passage that supported it.

Supported files

TXT, Markdown, CSV, PDF, and DOCX up to 10 MB. Text is extracted when the file is uploaded; the original stays in the sandbox upload folder.

What gets sent

Only the selected document ID and your question are sent to the Client. The document provider uses extractive retrieval, so it quotes rather than invents.

Citations

Each answer lists up to two cited passages with a relevance score. Open the full trace to inspect the task envelope and provider output.

Removing a file

Select the document and choose Remove. This deletes the record and the stored source file. Seeded demo data is never removed.

Evidence

Trust and verification

Trust is a posterior mean, not a declaration: (successes + 1) / (successes + failures + 2). A tool with no observations starts at the Beta(1,1) prior of 0.5.

  • Observations are real calls or probe results recorded in the trust ledger.
  • Auditor probes compare provider responses with the mapped catalogue schema and declared claims.
  • Circuit breakers isolate a provider after repeated failures; the Client then tries a type-compatible substitute.
  • Staging means a correction or listing is waiting for the Mapper. It is not rejected and it is not promoted.

Open the Trust Center to run a synchronous verification, inspect trust history, or replay a provider's score.

When something looks off

Troubleshooting

Why do I see a default trust score?

A score of 50% with no observations is the prior, not a failed test. Run a task or an Auditor probe to create evidence.

Why is Verify now disabled?

The Auditor only verifies tools that have a catalogue mapping. The console now selects the first mapped tool automatically; choose another from the list if needed.

Why did my document question return the wrong passage?

Retrieval is lexical and extractive. Ask about terms that appear in the document, or rephrase using the document's own vocabulary. The closest passage is returned when there is no direct match.

Why did a task use a different tool?

The Client substitutes a type-compatible provider when a circuit breaker is open or a call fails. The result and trace label the substitution and show the original provider.

Know the boundary

Demo limits

  • All providers are sandbox examples. Fixture responses may stand in for live network calls.
  • Task traces and uploaded documents persist across restarts; trust, breakers, drift alerts, and demo overrides reset when you use Reset demo.
  • Uploaded documents are private to this local sandbox and are not sent to an external service.
  • Trust evidence is scoped to this environment. A listing does not confer a production guarantee.
